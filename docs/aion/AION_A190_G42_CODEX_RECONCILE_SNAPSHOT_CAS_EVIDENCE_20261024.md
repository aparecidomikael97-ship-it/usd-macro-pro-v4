## Current G42 implementation

- **Opt-in LAB only** `ExecutionOutbox(...,strict_reconcile_snapshot_cas_lab=True)`. The reconciliation path captures the *local* `(state,attempts,lease_owner,lease_until,effect_ref)` on an initial SENT/UNCERTAIN row. It checks the snapshot after authorization callback, after `adapter.reconcile` getter, after adapter's reconciliation callback and before final status response. If changed, returns **the current row** with `G42_STALE_REPLY_NO_WRITE` rather than a misleading pre-callback UNCERTAIN or a failed confirmation.
- The `_confirm` path, when passed that snapshot, opens `BEGIN IMMEDIATE`, verifies row identity and phase prior to ledger insertion, then CASes state+attempts+lease owner/expiry+effect_ref in **the same transaction** as local `action_effects` insertion. On mismatch it rolls back; no phantom synthetic local effect is left.
- Codex-followup hardening for calls on the **strict LAB instance**: when `_confirm` receives neither dispatch's `fence_lab` nor reconciliation snapshot, repeating the SAME already-confirmed ref is a **read-only idempotent success**, preserving original `confirmed_at`, `effect_ref` and ledger. Conflicting ref/incoherent ledger rejects. Direct confirmation from REVOKED/FAILED is denied. Calls with dispatch fencing preserve G41 behavior.
- **No new physical SQLite columns, triggers or automatic historical migrations**. This tests application-level CAS against current schema. It is not versioned migration/readiness or proof against a hostile same-host replacement.
