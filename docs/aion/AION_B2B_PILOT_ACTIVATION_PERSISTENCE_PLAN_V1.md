# AION B2B Pilot Activation Persistence Plan V1\n\nStatus: **staging / patch candidate only / no checkpoint write**.\n\n## Objective\n\nPrepare a deterministic Checkpoint Master patch candidate for a verified\n`AUTHORIZE_PILOT_ACTIVATION` or `DENY_PILOT_ACTIVATION` record.\n\n## Accepted source\n\nThe source must be cryptographically verified and still pending persistence.\n\nIt must keep:\n\n- activation_record_persisted=false;\n- pilot_activation_authorized=false;\n- pilot_activated=false;\n- all external authority flags false;\n- activation decision and intent booleans consistent;\n- exact activation-record digest;\n- exact owner / tenant / workspace / candidate / proposal / pilot identity;\n- exact environment/preflight/request digests.\n\n## Checkpoint binding\n\nThe plan reconstructs the current Checkpoint Master and produces:\n\n- namespace `aion_b2b_pilot_activation_authorization`;\n- current expected revision;\n- deterministic event ID;\n- exact patch digest;\n- activation record still marked not persisted;\n- explicit-save and persistence-attestation requirements.\n\nThe module does not call `append_checkpoint_patch`.\n\n## AUTHORIZE semantics\n\nAn AUTHORIZE patch candidate may preserve the informational fact that activation\nexecution could become eligible only after persistence and attestation.\n\nIt still keeps:\n\n- pilot_activation_authorized=false;\n- pilot_activated=false;\n- checkpoint_saved=false;\n- automatic_checkpoint_write=false.\n\n## DENY semantics\n\nA DENY patch remains execution-ineligible.\n\n## Safety boundary\n\nThe plan never writes Checkpoint Master, claims persistence, authorizes\nactivation, activates a pilot, contacts a customer, bills, provisions, deploys\nor mutates production.\n
