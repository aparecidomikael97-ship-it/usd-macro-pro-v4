# AION V2 — unknown GitHub write outcome in three legacy evidence stores

**9 October 2026. Stacked Draft on #1152; strictly NO-GO for production deployment and any paid calls.**

## Real source risk before this change
#1152 rejects unexpected GitHub HTTP response statuses at all 21 mutation callsites. However, three existing JSONL stores — the Flight Recorder, Research Evidence, and Shadow Mode — still caught post-send timeouts and rejected/ambiguous HTTP responses as a generic `IO_ERROR`, without warning that the GitHub write *may have committed*. These functions offered an optional bounded conflict retry, but had no explicit contract distinguishing an unknown post-dispatch outcome from a proven rejected write. That makes it easy for a later caller to mistakenly treat an error as permission to replay. This is an identified code-level risk, not evidence of an actual double write.

## Changed in application functions (not only a reference helper)
- The three actual `persist_*` functions now track a conservative `write_attempted` boundary **immediately before their existing guarded `requests.put`**. If that boundary has been entered and response validation, transport, or parsing raises, return a structured **`UNKNOWN_OUTCOME`**, with `write_outcome="UNKNOWN"`, `reconciliation_required=True`, `safe_to_retry=False`, `write_attempted=True`. This does not make an additional request, refund or retry. `error` for this case contains only the exception **class name** and never a token or request body.
- Read/parsing failures before the PUT retain their previous `CORRUPT_REMOTE` / `IO_ERROR` classifications. Existing bounded retry is preserved **only for HTTP 409**, with a fresh read before the second and final attempt. A final 409 returns `CONFLICT` / `write_outcome="REPORTED_CAS_CONFLICT"` / `reconciliation_required=True`. Crucially, **HTTP 422 never retries**: GitHub may return 422 for validation/spam problems unrelated to CAS, so classifying it as an approved concurrency retry would be unsafe. 422 now returns `VALIDATION_REJECTED` / `write_outcome="REPORTED_HTTP_422"` / `reconciliation_required=True` / `safe_to_retry=False`. Neither status is independently authenticated as proof of a remote effect.
- On the 28 authenticated GitHub GET and 21 write paths, #1150–#1152 fixed-host/route checking, explicit no redirect and strict HTTP statuses remain in place; the two source-locked OpenAI inference/TTS billable POST paths remain hard-denied.
- New no-network regression tests patch each real `_fetch` and `requests.put`, inject ambiguous HTTP 302 with fake body and `requests.Timeout`, assert exactly one PUT on unknown outcome even with `retry_conflict_once=True`, test bounded 409 conflicts and *no* 422 replay and pre-send corrupt/read-timeout exceptions. Source contract audit checks all three functions. Ubuntu and Windows CI inherits full signed owner/witness/provider security regression stack.

## Remaining NO-GO
`UNKNOWN_OUTCOME` is conservative: entering the call expression does not prove any bytes reached the network. An HTTP 200/201 is still not an independently authenticated durable receipt; these stores retain legacy `SAVED` on that status without remote read-after-write, so it is **NOT a certification of persistence**. A caller could still invoke the function again separately; this PR labels it unsafe but does not implement a global protected one-shot journal or trusted monotonic CAS. Even conflict codes rely on an unproven response origin. No independent enrolled HUMAN_OWNER, real external witness roots, FIDO2/TPM custody, physical sandbox, FinOps settlement, provider idempotency, live network/DNS/proxy assurance or deployment approval exists.
